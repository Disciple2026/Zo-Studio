# Feuille de route

| Phase | Contenu | Validation | État |
| --- | --- | --- | --- |
| 0 | Audit, gouvernance, agents, skills, documentation, garde-fou d'indépendance | Le propriétaire comprend l'architecture et les fichiers créés | **Terminée, à valider** |
| 1 | Design system émeraude et or, navigation, nouvel accueil avec aperçu du simulateur | Parcours principal testable sur mobile et ordinateur | À venir |
| 2 | Flux Explorer, bibliothèque, filtres, fiches, favoris locaux | Découverte fonctionnelle avec données de démonstration étiquetées | |
| 3 | Simulateur « Zoé Site Studio » | Chaque choix modifie réellement l'aperçu et le brief | |
| 4 | Services, packs, brief, WhatsApp | Une demande arrive de façon fiable dans l'administration | |
| 5 | Supabase : Auth, RLS, catalogue, médias, prompts, clients | Tests d'accès positifs et négatifs réussis | |
| 6 | Espace client : favoris, simulations, briefs, commandes, fichiers | Un client ne voit que ses données | |
| 7 | Zoé Experience Lab | Une démo se publie sans affecter le site principal | |
| 8 | Sécurité, tests, SEO, performance, accessibilité, production | Approbation explicite du propriétaire | |
| Plus tard | Assistant IA public | Hors première livraison | |

La première démo du Lab (prompt Gravity, sans aucune ressource à produire) peut être avancée en
parallèle de la phase 1 pour valider la chaîne de recréation.

## Décisions attendues du propriétaire

1. Devenir de l'activité vidéo événementielle dans la nouvelle plateforme (hypothèse : conservée
   comme entrée « Vidéo »).
2. Logo : garder, décliner ou redessiner.
3. Hébergement des prévisualisations : Vercel ou GitHub Pages.
4. Visuels : quelles photos et vidéos réelles du studio peuvent être utilisées.
5. Dépôt public ou privé.
